# 前端部署

VMP 前端是由 Nginx 托管的纯静态页面。浏览器只访问同源 `/api/`，Nginx 将请求代理到名为 `control-plane`、端口为 `8080` 的后端服务。

## 推荐方式：完整 Compose

只需克隆后端仓库，然后在后端目录执行：

```bash
cd vmp-backend
cp .env.example .env
chmod 600 .env
docker compose --env-file .env -f deployments/compose/compose.yaml up -d
```

该方式会从 Docker Hub 拉取后端 Compose 默认指定的前端版本，并同时启动 PostgreSQL、控制面和 Web，默认访问 `http://服务器地址:8080`。系统要求、密钥、数据库、Agent、升级与备份见后端仓库 `docs/部署指南.md`。

升级 `0.5.1` 必须配套后端、前端和 Agent，先备份数据库、原静态目录、Nginx 与 Agent 配置，并暂停宿主调度。在后端 `.env` 中设置 `VMP_FRONTEND_IMAGE=lixiaokun/vmp-frontend:0.5.1`、`VMP_BACKEND_IMAGE=lixiaokun/vmp-backend:0.5.1`，按后端部署文档完成自动迁移 `019/020`、独立宿主凭据与 Agent 升级，再检查镜像宿主就绪并恢复调度：

```bash
docker compose --env-file .env -f deployments/compose/compose.yaml pull control-plane web
docker compose --env-file .env -f deployments/compose/compose.yaml up -d control-plane web
```

静态文件挂载部署需整体替换 `web/`（包括 `platform.js`、`console.js`、`console.html`、全部样式、noVNC/xterm `vendor/` 与许可），同时替换生效的 `deployments/nginx.conf` 并执行 `nginx -t` / 重载。不能只复制旧脚本清单；旧标签页需刷新后携带新的安全写请求头。Agent 依赖缺失时保持只读或暂停调度，不能假称已有创建/控制台能力。升级流程和回滚约束以配套后端/Agent 文档为准，不在此对数据库做手工 SQL 操作。

需要修改前端源码时，把前后端仓库放在同一父目录，并叠加源码构建配置：

```bash
docker compose --env-file .env \
  -f deployments/compose/compose.yaml \
  -f deployments/compose/compose.build.yaml \
  up -d --build web
```

## 单独构建前端镜像

```bash
docker build -t vmlease-web:local .
```

国内网络需要替换基础镜像时可以传入：

```bash
docker build \
  --build-arg NGINX_IMAGE=你的可信镜像仓库/nginx:1.30.5-alpine \
  -t vmlease-web:local .
```

前端容器必须和后端容器位于同一 Docker 网络，并且后端在该网络中的 DNS 名称为 `control-plane`：

```bash
docker network create vmlease-network
docker network connect --alias control-plane vmlease-network 后端容器名称
docker run -d \
  --name vmlease-web \
  --network vmlease-network \
  --restart unless-stopped \
  -p 8080:80 \
  vmlease-web:local
```

如果组织已有 Kubernetes、Nginx Ingress 或其他网关，可以直接托管 `web/` 目录，但必须保留以下路由规则：

- `/`：静态文件，未命中文件时回退到 `/index.html`；
- `/api/`：反向代理到控制面；
- 把可信客户端地址写入 `X-Real-IP` 和 `X-Forwarded-For`；
- 禁止长期缓存 `index.html`，避免 HTML 与 JavaScript 版本不一致。

## 浏览器安全头与控制台

使用仓库 Nginx 配置时，默认返回 CSP、`X-Content-Type-Options: nosniff`、禁止嵌入的 `X-Frame-Options`、无 Referrer 及权限策略。自建网关托管 `web/` 时必须同步这些头，不能只复制静态文件：

```text
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ws://平台host:port wss://平台host:port; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

脚本不允许 `unsafe-inline` 或 `unsafe-eval`。样式的 `unsafe-inline` 仅为第一方进度条、noVNC/xterm 动态布局保留；不要据此放宽脚本。控制台仅连接同源桥接；配置用 `$http_host` 生成当前 Host 的明确 WS 源，不允许宽泛 `ws:` / `wss:`。

Nginx 子 `location` 一旦单独定义 `add_header`，可能不继承父级安全头。因此仓库把缓存与安全头都定义在 server 层；自建网关配置后应实际检查首页与控制台响应。只替换 HTML/JS 无法更新 Nginx 安全头，需同时更新配置并重建 / 重载 Web 服务。

控制台地址栏不再接收连接 URL 或票据。窗口向同源 `console-sessions` API 申请相对同源桥接地址，验证 Host、模式路径、协议；Agent 端口只需控制面可达，不需要向浏览器用户开放。Agent 白名单和一次性核销仍保留。

`/api/` 反向代理必须支持 WebSocket：HTTP/1.1、Upgrade/Connection 转发、完整 `Host $http_host`（含端口）和合理的 `proxy_read_timeout`。仓库配置包含 `map $http_upgrade`；自建外部网关也必须保留升级头。配置变化后执行 `nginx -t` 并重载，不能仅替换网页文件。

WebSocket 票据位于握手查询参数中，访问日志必须使用不含 query string 的安全格式。仓库 `vmp_safe_access` 只记录 `$uri`，不记录 `$request` 或 `$request_uri`；外部网关也应同样过滤，禁止把短时票据写入日志。

## HTTPS

生产环境应使用 HTTPS。TLS 可以在外部负载均衡器或前置反向代理终止，再转发到前端容器的 HTTP 端口。

启用 HTTPS 后，后端环境变量必须设置：

```dotenv
SESSION_COOKIE_SECURE=true
```

浏览器访问同源 WSS，由平台 HTTPS 网关终止 TLS。Agent 的控制台地址是控制面到宿主机的受控内部地址，不再要求各宿主单独提供浏览器可访问的 WSS。按后端部署文档限制端口仅控制面可达。

## 健康检查

```bash
curl -I http://127.0.0.1:8080/
curl http://127.0.0.1:8080/api/v1/health
```

第一个请求验证静态页面，第二个请求同时验证 Nginx 到控制面的代理链路。

## 升级

```bash
git pull --ff-only
docker build -t vmlease-web:新版本 .
```

使用官方镜像的完整 Compose 时：

```bash
cd ../vmp-backend
docker compose --env-file .env -f deployments/compose/compose.yaml pull web
docker compose --env-file .env -f deployments/compose/compose.yaml up -d web
```

升级后如果浏览器显示旧页面，先确认服务端 `index.html` 已更新，再执行普通刷新。仓库已对静态页面返回禁用长期缓存响应，不应要求用户长期清理浏览器缓存。

## 常见问题

### 页面可以打开，但所有数据请求失败

查看前端日志，并确认控制面容器健康、服务名为 `control-plane`：

```bash
docker logs --tail=200 vmlease-web
docker inspect vmlease-web
```

### 登录成功后又回到登录页

HTTP 部署时后端 `SESSION_COOKIE_SECURE` 必须为 `false`；HTTPS 部署时应为 `true`。同时检查浏览器请求是否始终使用同一域名和协议。

### 控制台被浏览器拒绝

确认平台外部网关和 Web Nginx 都支持 `/api/` 的 WebSocket 升级，控制面能够访问 Agent 内部代理地址，Origin/票据仍满足后端及 Agent 校验。浏览器只需访问平台 HTTPS/WSS；不能通过放宽 CSP 为任意 WS 主机解决问题。
