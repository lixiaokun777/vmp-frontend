# 前端部署

VMP 前端是由 Nginx 托管的纯静态页面。浏览器只访问同源 `/api/`，Nginx 将请求代理到名为 `control-plane`、端口为 `8080` 的后端服务。

## 推荐方式：完整 Compose

只需克隆后端仓库，然后在后端目录执行：

```bash
cd vmp-backend
cp .env.example .env
chmod 600 .env
docker compose --env-file .env -f deployments/compose/compose.yaml up -d
```

该方式会从 Docker Hub 拉取后端 Compose 默认指定的前端版本，并同时启动 PostgreSQL、控制面和 Web，默认访问 `http://服务器地址:8080`。系统要求、密钥、数据库、Agent、升级与备份见后端仓库 `docs/部署指南.md`。

升级到包含群机器人设置的前端 `0.4.2` 时，在后端 `.env` 中设置 `VMP_FRONTEND_IMAGE=lixiaokun/vmp-frontend:0.4.2`，配合后端 `0.4.3`，然后执行：

```bash
docker compose --env-file .env -f deployments/compose/compose.yaml pull web
docker compose --env-file .env -f deployments/compose/compose.yaml up -d web
```

静态文件挂载部署需同时替换 `index.html`、`app.js`、`notifications.js`、`styles.css`、`v1.css`，避免新脚本和旧样式混用。后端自动执行 `015_group_notifications.sql`，Agent 无需更新。管理员在“通知设置”保存机器人、发送测试并启用自动通知；凭据由后端配置密钥加密保存。

需要修改前端源码时，把前后端仓库放在同一父目录，并叠加源码构建配置：

```bash
docker compose --env-file .env \
  -f deployments/compose/compose.yaml \
  -f deployments/compose/compose.build.yaml \
  up -d --build web
```

## 单独构建前端镜像

```bash
docker build -t vmlease-web:local .
```

国内网络需要替换基础镜像时可以传入：

```bash
docker build \
  --build-arg NGINX_IMAGE=你的可信镜像仓库/nginx:1.27-alpine \
  -t vmlease-web:local .
```

前端容器必须和后端容器位于同一 Docker 网络，并且后端在该网络中的 DNS 名称为 `control-plane`：

```bash
docker network create vmlease-network
docker network connect --alias control-plane vmlease-network 后端容器名称
docker run -d \
  --name vmlease-web \
  --network vmlease-network \
  --restart unless-stopped \
  -p 8080:80 \
  vmlease-web:local
```

如果组织已有 Kubernetes、Nginx Ingress 或其他网关，可以直接托管 `web/` 目录，但必须保留以下路由规则：

- `/`：静态文件，未命中文件时回退到 `/index.html`；
- `/api/`：反向代理到控制面；
- 把可信客户端地址写入 `X-Real-IP` 和 `X-Forwarded-For`；
- 禁止长期缓存 `index.html`，避免 HTML 与 JavaScript 版本不一致。

## HTTPS

生产环境应使用 HTTPS。TLS 可以在外部负载均衡器或前置反向代理终止，再转发到前端容器的 HTTP 端口。

启用 HTTPS 后，后端环境变量必须设置：

```dotenv
SESSION_COOKIE_SECURE=true
```

如果页面使用 VNC/串口控制台，各宿主机的 `CONSOLE_PUBLIC_URL` 必须是浏览器可访问的 `wss://` 地址，不能从 HTTPS 页面连接 `ws://`。

## 健康检查

```bash
curl -I http://127.0.0.1:8080/
curl http://127.0.0.1:8080/api/v1/health
```

第一个请求验证静态页面，第二个请求同时验证 Nginx 到控制面的代理链路。

## 升级

```bash
git pull --ff-only
docker build -t vmlease-web:新版本 .
```

使用官方镜像的完整 Compose 时：

```bash
cd ../vmp-backend
docker compose --env-file .env -f deployments/compose/compose.yaml pull web
docker compose --env-file .env -f deployments/compose/compose.yaml up -d web
```

升级后如果浏览器显示旧页面，先确认服务端 `index.html` 已更新，再执行普通刷新。仓库已对静态页面返回禁用长期缓存响应，不应要求用户长期清理浏览器缓存。

## 常见问题

### 页面可以打开，但所有数据请求失败

查看前端日志，并确认控制面容器健康、服务名为 `control-plane`：

```bash
docker logs --tail=200 vmlease-web
docker inspect vmlease-web
```

### 登录成功后又回到登录页

HTTP 部署时后端 `SESSION_COOKIE_SECURE` 必须为 `false`；HTTPS 部署时应为 `true`。同时检查浏览器请求是否始终使用同一域名和协议。

### 控制台被浏览器拒绝

确认页面 Origin 已加入 Agent 的 `CONSOLE_ALLOWED_ORIGINS`，HTTPS 页面使用 `wss://`，并确认宿主机控制台代理端口可达。
